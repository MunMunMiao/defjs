# Проектные решения

Здесь объясняются причины устройства текущего API. Поля и значения по умолчанию описаны на справочных страницах.

## Явные клиенты

В Defjs нет общего клиента по умолчанию на весь процесс. `createClient(...)` делает владельца видимым в месте вызова и позволяет приложению создавать разные клиенты для разных эндпоинтов, учётных данных, тестов или областей запроса.

У этой изоляции есть пределы. Перехватчики и колбэки опций могут замыкать общее состояние приложения, поэтому два объекта клиента не изолированы автоматически от всего окружения. Кроме того, `setErrorMap(...)` действует на весь процесс. Серверный код должен создавать клиент в области запроса, если опции или замыкания содержат данные запроса, пользователя, арендатора, cookie или авторизации.

Явный клиент упрощает разговор о владении ресурсами, но сам не управляет ими. Он не отслеживает и не освобождает активные HTTP-запросы, хендлы SSE или сеансы WebSocket.

## Кортежи с учётом транспорта

Все поддерживаемые команды возвращают трёхэлементный кортеж с ошибкой на первом месте, но третий элемент сохраняет смысл конкретного транспорта:

```typescript
const [httpError, data, response] = await client.execute(httpCommand)
const [sseError, stream, startupOpen] = await client.execute(sseCommand)
const [socketError, session, startupConnection] = await client.execute(socketCommand)
```

Так обёртка HTTP-ответа, снимок открытия SSE при запуске и снимок подключения WebSocket при запуске не сводятся к одной расплывчатой абстракции. Второй элемент устроен так же: HTTP возвращает декодированные данные, SSE — логический хендл потока, WebSocket — логический сеанс.

Кортеж явно представляет ожидаемые ошибки запуска и не навязывает управление через исключения. Но это не обещание, что произвольные перехватчики, колбэки, слушатели или неподдерживаемые значения никогда не приведут к отклонению Promise или синхронному исключению.

## Опции жизненного цикла задаются при выполнении

Описание эндпоинта фиксирует стабильный сетевой контракт. Отмена, тайм-аут, heartbeat, переподключение и очереди относятся к конкретному выполнению, которое владеет работой.

HTTP и SSE принимают опции отмены при выполнении. WebSocket также принимает для отдельного запуска опции подключения, heartbeat, переподключения, протокола и очереди отправки. Опции клиента задают переиспользуемые значения по умолчанию там, где транспорт это поддерживает.

Так одну команду можно переиспользовать. Фоновая задача и интерактивный экран выполняют её с разным временем жизни, не переопределяя путь или схему сообщений.

## `build` работает с проекциями

Пользовательский `build(request, input)` получает декларативное представление привязок, построенное из входного Struct. Значения, переданные вызывающим кодом, ему недоступны.

Это представление хранит соответствие исходных полей параметрам пути, query, заголовкам и телу. Модель поддерживает выбор полей, явные сетевые ключи и проекцию массива один к одному. Она намеренно не позволяет ветвиться по значениям, выполнять произвольные преобразования или добавлять литералы в проекцию.

Так построение запроса остаётся привязано к полям объявленного Struct. Нормализацию и бизнес-проверки выполняйте до создания команды. Поддерживаемые формы проекций перечислены в разделе [«Команды»](/ru-RU/core/commands).

## Наблюдатели не управляют потоком выполнения

SSE `onInvalidEvent` наблюдает за отброшенными событиями. Выброшенная ошибка или отклонённый результат наблюдателя перехватываются и не завершают поток, хотя асинхронного наблюдателя ждут, поэтому он может задержать обработку следующих сообщений.

Слушатели состояния и ошибок WebSocket во время выполнения тоже являются наблюдателями, но текущая реализация вызывает их напрямую. Делайте их синхронными, короткими и не выбрасывающими ошибки. Исключение из слушателя может нарушить работу жизненного цикла и не является поддерживаемым способом управления им.

Решения по жизненному циклу принимайте через возвращённый хендл или сеанс. Наблюдатели подходят для ограниченного логирования, метрик и обновления состояния; удаляйте их при уничтожении владельца.
