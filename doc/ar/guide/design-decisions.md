# قرارات التصميم

Defjs تختار مقايضات متعمّدة. واجهات الراحة غالبًا تخفي من يملك الطلب أو التدفق أو الجلسة. Defjs تُبقي ذلك الحد ظاهرًا لتعيد استخدام عقد نقطة النهاية نفسه دون التقاط cache أو مجدول إعادة محاولة أو مدير موارد بصمت.

## الإعلان هو تأكيد

هذه القواعد الست تحسم كل سؤال عن كيفية قراءة الاستجابة. وهي مرقّمة حتى يتمكن أي نقاش لاحق من الإحالة إلى واحدة منها بدل إعادة استنتاجها.

### 1. ما تُعلنه هو ما تؤكّده

`output` يعني: «حين يكون `ok` صحيحًا، فإن الجسم **هو** هذا الشكل». و`error` يعني: «حين يكون `ok` خطأً، فإن الجسم **هو** هذا الشكل». الإعلان ليس تلميحًا ولا أملًا ببذل أفضل جهد، بل ادّعاء عمّا سيصل.

### 2. `ok` هو نقطة التفرّع الوحيدة، ولا يُفكّ إلا طرف واحد

استجابة 2xx تُقرأ بـ `output`. وكل ما عداها يُقرأ بـ `error`. لا الاثنان معًا أبدًا، ولا الآخر كبديل احتياطي.

### 3. الواقع المخالف للتأكيد فشلٌ يُبلَّغ عنه بصراحة

لا تخمين للصيغ، ولا هبوط إلى شيء أضعف، ولا صمت. سواء تغيّر الخادم، أو تدخّلت بوابة، أو تلاعب أحدهم بالاستجابة، فذلك **لا يغيّر الاستنتاج** — المكتبة لا تستطيع التمييز بينها ولا ينبغي أن تتظاهر بذلك.

هذه هي القاعدة التي يُطلب تلطيفها أكثر من غيرها، فيستحق الأمر عرض الحالة بوضوح. لنفترض أن مهاجمًا يستطيع إعادة كتابة `200` كانت صفحتك على وشك قراءتها بـ `output`، فوصلك بدلًا منها `3xx` أو `4xx` أو `5xx`. الفشل ليس إزعاجًا، بل هو النتيجة الآمنة الوحيدة. ومنحُك الجسم الخام «تحسّبًا» يعطي كل من يقدر على حقن استجابة طريقًا لتجاوز التحقق الذي طلبته أنت.

### 4. الفكّ الفاشل لا جسم له

الجسم **هو** القيمة المفكوكة. فإذا فشل الفكّ فلا قيمة — ولا جسم نصف مفكوك لتتفقّده. التفصيل المسبِّب يعيش على `cause`؛ والاستجابة تحتفظ ببياناتها الوصفية ولا شيء غير ذلك.

هذه القاعدة يفرضها نظام الأنواع لا العُرف: فحقل `response` في خطأ الفكّ هو `HttpMeta`، وهو لا يملك حقل `body` إطلاقًا، فمحاولة الوصول إليه خطأ في الترجمة.

### 5. إن لم ترغب في التأكيد، فلا تُعلن

حذف `output` يعني «لا يهمّني جسم 2xx» — فلن يُقرأ أبدًا. وحذف `error` يقول الشيء نفسه عن كل ما عداه. هذا انسحاب صريح لا سهو، وهو يمضي إلى النهاية: جسم غير قابل للقراءة في الطرف الذي انسحبت منه ليس شأنك، ولا حتى كونه غير قابل للقراءة.

### 6. 3xx ليس نطاق رموز أخطاء

إن كنت تعرف أن نقطة نهاية تجيب بحالة إعادة توجيه، فلا تُعطِ `output` مخططًا لها، أو أعلن مخططًا يقبل قيمة فارغة. وإلا فالإبلاغ عن فشل هو النتيجة المتوقعة لا ثغرة.

## عملاء صريحون

`createClient(...)` يجعل إعداد نقطة النهاية قيمة صريحة. البيئات أو نطاقات الطلب المختلفة تحصل على نقاط نهاية وبيانات اعتماد ومعترضات ومُسلسلات ومعالجات نقل مختلفة. `createClient(...)` من `@defjs/core` يفعل الشيء نفسه لمستهلكي HTTP فقط.

التكلفة: لا افتراضي على مستوى العملية. هذه التكلفة تفيد على الخادم — أنشئ العميل داخل حدود الطلب عندما تلتقط الخيارات أو الإغلاقات المصادقة أو ملفات تعريف الارتباط أو المستخدمين أو المستأجرين أو بيانات تعريف الطلب. العميل الصريح لا يعزل الحالة التي يلتقطها معترض، هوية العميل ليست حد أمان بذاتها.

العميل يوزّع الأوامر. لا يملك العمل النشط. من يبدأ طلب HTTP أو تدفق SSE أو جلسة WebSocket يجب أن يلغي أو يغلق وينتظر الوعد النهائي.

## التعريفات والمنشئات والأوامر

التعريف هو العقد المستقر: الطريقة، المسار، Struct المدخل، خريطة المخرج، حدود النقل. المنشئ هو الواجهة القابلة للاستدعاء. استدعاؤه ينشئ أمرًا معتمًا واحدًا لتنفيذ واحد.

```typescript twoslash
import { defineRequest, struct } from '@defjs/core'

const getUser = defineRequest({
  method: 'GET',
  path: '/users/:id',
  input: struct.request({
    path: struct.object({ id: struct.number() }),
  }),
  output: struct.object({ id: struct.number(), name: struct.string() }),
  error: struct.object({ message: struct.string() }),
})

const command = getUser({ path: { id: 7 } })
```

مهمة خلفية ومالك واجهة يمكنهما تنفيذ نفس شكل `getUser` بسياسات إلغاء/إعادة محاولة مختلفة. إبقاء الأمر معتمًا يمنع كود التطبيق من الاعتماد على علامات النقل الداخلية أو الرموز.

## نتائج خاصة بوسيلة النقل

وسائل النقل الثلاث تستخدم tuple يضع الخطأ أولاً. «استجابة» عامة واحدة ستمحو حقائق دورة الحياة.

- HTTP → `[error, data, response]` — مخرج مفكوك + `HttpResponse`
- SSE → `[error, stream, open]` — تدفق منطقي واحد + لقطة استجابة البدء
- WebSocket → `[error, session, connection]` — جلسة منطقية + لقطة اتصال البدء

القيمة الثالثة لقطة، وليست وعدًا بأن إعادة الاتصال اللاحقة تبقي نفس الاتصال المادي. فشل البدء قد يتضمن استجابة/لقطة عندما أنتجت وسيلة النقل واحدة أولاً. بعد البدء، التحكم بدورة الحياة يعود للمعالج أو الجلسة المُرجَعة.

## الفك وقت التشغيل

استنتاج TypeScript يصف ما تتوقعه؛ لا يتحقق من استجابة الخادم وقت التشغيل. تحليل Struct هو النصف الثاني من العقد. Defjs تتحقق من مدخل الأمر قبل بناء الطلب، وتفك التمثيل المختار، ثم تحلّل Struct المطابق.

الفكّ يحدث **مرة واحدة، بعد سلسلة المعترضات**. والاستجابة التي بناها معترض بـ `makeResponse(...)` تُفسَّر تمامًا كتلك القادمة من الشبكة: مصدر الاستجابة لا يغيّر طريقة قراءتها، فلا يوجد مسار «ثِق بالمعترض» يحتاج تفكيرًا.

الترتيب هو: نوع الوسائط، ثم التمثيل، ثم Struct.

| ما لم يصمد                                | الخطأ                                                  |
| ----------------------------------------- | ------------------------------------------------------ |
| نوع الوسائط ليس ما يحتاجه التمثيل المعلَن | `RES_MEDIA_TYPE_INVALID` — يُبلَّغ **قبل** قراءة الجسم |
| البايتات ليست ذلك التمثيل                 | `RES_DECODE_FAILED`                                    |
| القيمة ليست ذلك الـ Struct                | `RES_STRUCT_MISMATCH`                                  |
| غير-2xx، و`error` فُكّ بنجاح              | `HTTP_STATUS` مع `data` مُنوَّع                        |
| غير-2xx، و`error` غير معلَن               | `HTTP_STATUS` مع `data: undefined`                     |

فحص نوع الوسائط أولًا هو ما يحوّل «طلبت JSON فوصلني HTML» إلى خطأ واحد دقيق بدل خطأ محلِّل، وهو يتخطى القراءة والتحليل و Struct بالكامل.

## حدود `build`

تعيين `struct.request(...)` التلقائي هو الافتراضي عندما يملك المدخل بالفعل path/query/headers/body. `build(request, input)` المخصص إسقاط مقيّد عندما يختلف شكل المستدعي عن شكل السلك:

```typescript twoslash
import { defineRequest, struct } from '@defjs/core'

const createBatch = defineRequest({
  method: 'POST',
  path: '/accounts/:account_id/users',
  input: struct.object({
    accountId: struct.number(),
    users: struct.array(
      struct.object({
        displayName: struct.string(),
        email: struct.string(),
      }),
    ),
  }),
  build(request, input) {
    request.setPathParams({ account_id: input.accountId })
    request.setJson({
      users: input.users.map((user) => ({
        display_name: user.displayName,
        email: user.email,
      })),
    })
  },
  output: struct.object({ accepted: struct.number() }),
})

const command = createBatch({
  accountId: 42,
  users: [{ displayName: 'Ada', email: 'ada@example.com' }],
})
```

`input` عرض مقيّد بالمخطط، وليس كائن وقت تشغيل المستدعي. الإسقاط يمكنه اختيار الحقول المعلَنة، وإعادة تسمية الأهداف، وتعيين عنصر مصفوفة مصدر واحد إلى عنصر مخرج واحد. لا يمكنه التفريع على القيم، أو حقن ثوابت، أو تغيير العددية. طبّع بيانات العمل وقم بالتحقق المعتمد على القيمة قبل إنشاء الأمر.

## المراقبون وموضع السياسة

المعترضات لسياسة النقل العامة: مصادقة، تتبّع، قطع قصير، إعادة محاولة مراجعة. تعمل فقط لوسيلة نقلها وتتركّب بترتيب البصلة. خيارات التنفيذ لعمر العمل المحدد: `signal`، `timeout`، نبض WebSocket، إعادة اتصال اختيارية.

المراقبون يُبلّغون بما حدث دون أن يصبحوا مالكًا ثانيًا. `onInvalidEvent` في SSE، ومستمعو حالة WebSocket، ومستمعو أخطاء وقت التشغيل للتشخيص والمقاييس المحدودة. التدفق/الجلسة المُرجَعة ما زالت تملك التكرار والإغلاق وإلغاء الاشتراك وانتظار النهاية. التخزين المؤقت وقمع النتائج القديمة والتكرار الآمن وتعيين أخطاء المجال تنتمي حول `client.execute(...)`، حيث يرى تطبيقك سياسته وحالته.

## OpenAPI وخرائط المصدر والقياس عن بُعد

Defjs لا تولّد أو تزامن عقد OpenAPI ثانيًا. إذا كان OpenAPI هو المرجع، أبقِه وأضف تحققًا وقت التشغيل عند حدود التطبيق. لخدمة جديدة، تعريفات نقاط النهاية وStructs يمكن أن تكون عقد السلك المباشر — بلا مصدر حقيقة ثانٍ.

`withOpenTelemetryServer(...)` يضيف أجهزة Defjs **الصادرة** إلى عميل. لا يهيئ OpenTelemetry SDK. `tracer` مطلوب، و`meter` اختياري، ووسائل النقل الثلاث مفعّلة افتراضيًا، وانتشار استعلام WebSocket معطّل افتراضيًا. أبقِ أسماء العمليات ثابتة ومنخفضة الكاردينالية. راجع الانتشار والخطافات وعناوين URL والرؤوس والحمولات والأسباب والاحتفاظ كمحتوى حسّاس محتمل.

خرائط المصدر قرار نشر، وليست سلوك Defjs. خريطة عامة مع `sourcesContent` تكشف المصدر؛ خريطة مخفية ما زالت تحتوي المصدر والمسارات؛ تعطيل الخرائط يزيل الرمزية على مستوى المصدر. عامل الخرائط الخاصة كقطع تصحيح قابلة للنشر بقواعد وصول واحتفاظ صريحة.
