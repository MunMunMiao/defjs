# Core Type Unsafety Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除或收敛 `packages/core`（含测试与 core 配置脚本）中的类型强制断言、类型绕过和运行时边界不安全点，同时保护当前为了 TypeScript 推理而存在的特殊写法。

**Architecture:** 先把真实不安全点按边界收敛：struct runtime、request builder、command dispatch、JSON/runtime boundary、test mock/invalid fixture。推理敏感面不做机械替换：`as const`、`satisfies`、负向类型测试的 `@ts-expect-error`、`struct.any()` 和 public phantom generic surface 先由类型测试锁住，再只把散落强转搬进小而命名的边界 helper。

**Tech Stack:** TypeScript 6 / tsgo, pnpm 11, Vitest runtime tests, Vitest `--typecheck.only` type tests, Oxlint/Oxfmt, tsdown.

## Global Constraints

- 不改变 core 的运行时语义，除非某个任务显式写出对应测试与期望行为。
- 不新增依赖。
- 不机械删除 `as const` 和 `satisfies`；它们是字面量保持与推理锚点。
- 不机械删除 `*.type.test.ts` 中的 `@ts-expect-error`；负向 public API 测试应该继续让 TypeScript 证明错误调用无法通过。
- 不把 `AnyStruct = Struct<any, any, boolean>`、`createAnyStruct(): Struct<unknown, any>`、`ObjectShape = { [key: string]: any }` 直接改成 `unknown`。这些是当前 struct API 推理边界，必须先有类型矩阵证明替代方案不污染或不丢失推理。
- 不破坏 Go `encoding/json` 对齐的零值默认值与 partial input 语义：缺字段填零值、`.optional()` 控制 output 可省、request/object input 可 partial。
- 不把 public builder 改成显式宽类型从而掩盖推理：`defineRequest`、`defineEventStream`、`defineWebSocket`、`Client.execute`、`RequestBuildInput` 的 call-site 推理必须保持。
- 新增的类型边界必须命名、局部、带注释，并用 runtime test 或 type test 证明。目标不是把 `as` 从视野里藏起来，而是把无法避免的 TypeScript 边界集中到少数可信入口。
- 每个实现任务完成后至少运行：`pnpm --filter @defjs/core typecheck`。触碰推理敏感面时还要运行：`pnpm --filter @defjs/core test:type`。

## Type Inference Preservation Contract

1. Keep the phantom generic surface intact unless type tests prove otherwise:

```ts
export interface StructLike<I = unknown, O = unknown, OO extends boolean = boolean> {
  readonly [TYPES]: StructTypes<I, O, OO>
  readonly _struct: StructTypes<I, O, OO>
}
```

2. Keep these inference aliases behaviorally stable: `Infer<T>`, `FieldOutput<S>`, `ObjectInput<T>`, `ObjectOutput<T>`, `TupleOutput<T>`, `UnionOutput<T>`, `RequestInput<T>`, `RequestOutput<T>`, `EndpointInput<T>`, `ParsedInput<T>`.
3. Keep const tuple inference for enum/tuple/union/discriminated-union constructors. Replacing `const T extends readonly [...]` with broad arrays is a regression even if runtime tests pass.
4. Keep negative API tests as direct invalid expressions with `@ts-expect-error` where the directive is the proof.
5. Allowed named boundaries after review: `castStruct()`, a new `toRuntimeStruct()`/`toRuntimeStructs()` helper, builder materialization guards, typed test mock factories, and invalid runtime call helpers.

Required smoke matrix before merging any inference-sensitive task:

```ts
import { expectTypeOf } from 'vitest'
import { createClient } from '../client'
import type { HttpAwaitResult } from '../http'
import { defineRequest } from '../http'
import { defineEventStream } from '../sse'
import { defineWebSocket } from '../web_socket'
import { struct, type Infer } from '../struct'

const objectStruct = struct.object({
  id: struct.string(),
  nickname: struct.string().optional(),
  count: struct.number(),
})
expectTypeOf<Infer<typeof objectStruct>>().toEqualTypeOf<{ id: string; nickname?: string; count: number }>()

const tupleStruct = struct.tuple([struct.literal('ok'), struct.number()] as const)
expectTypeOf<Infer<typeof tupleStruct>>().toEqualTypeOf<['ok', number]>()

const unionStruct = struct.or(struct.literal('a'), struct.literal('b'), struct.number())
expectTypeOf<Infer<typeof unionStruct>>().toEqualTypeOf<'a' | 'b' | number>()

const request = defineRequest({
  method: 'GET',
  path: '/users/:id',
  input: struct.object({ id: struct.number() }),
  output: { 200: struct.object({ name: struct.string() }) },
})
expectTypeOf(request).toBeCallableWith({ id: 1 })
// @ts-expect-error required input must stay required
request()

const optionalRequest = defineRequest({ method: 'GET', path: '/users', output: { 200: struct.object({}) } })
expectTypeOf(optionalRequest).toBeCallableWith()

const client = createClient()
expectTypeOf(client.execute(request({ id: 1 }))).toEqualTypeOf<Promise<HttpAwaitResult<{ name: string }, unknown>>>()

const events = defineEventStream({
  path: '/events',
  events: { user: struct.object({ id: struct.string() }), default: struct.string() },
})
expectTypeOf(events).toBeCallableWith()

const socket = defineWebSocket({
  path: '/socket',
  incoming: { message: struct.object({ text: struct.string() }) },
  outgoing: { send: struct.object({ text: struct.string() }) },
})
expectTypeOf(socket).toBeCallableWith()
```

## Finding Groups

### Group A — Struct runtime struct casts

**Primary files:** `packages/core/src/struct/runtime.ts`, `constructors.ts`, `parse.ts`, `encode.ts`, `shape.ts`, `introspection.ts`, `codec/common.ts`, `codec/query.ts`, plus callers in `internal/request_builder.ts`.

**Observed unsafe patterns:** repeated `struct as unknown as RuntimeStruct`, `fieldStruct as RuntimeStruct`, `definition.struct as RuntimeStruct`, `value as never`, and explicit `any` at `struct.any` / `ObjectShape`.

**Risk:** medium. Most casts are currently legitimate TypeScript/runtime impedance mismatches, but the repetition makes real mismatches indistinguishable from inference plumbing.

**Target:** keep one or two named runtime boundary helpers and replace scattered double assertions with those helpers. Keep `struct.any` and `ObjectShape` public behavior until the type matrix passes.

### Group B — Request builder projection/materialization casts

**Primary file:** `packages/core/src/internal/request_builder.ts`.

**Observed unsafe patterns:** casts from struct sections to `RuntimeStruct`, materialized projections to `RequestBuildValue` / `RequestFormDataValue`, raw body to `HttpRequest['body']`, and runtime proxies to `RequestBuildInput<TInput>`.

**Risk:** high. This file bridges user input, request serialization, and generic builder inference. A wrong “cleanup” can silently break build() DX.

**Target:** do not rewrite public `RequestBuildInput` inference. Add runtime guards for flat values, body values, form data values, and isolate unavoidable proxy casts in `createTypedBuildInput`.

### Group C — Command dispatch and endpoint builder casts

**Primary files:** `packages/core/src/client/client.ts`, `packages/core/src/http/http.ts`, `packages/core/src/sse/sse.ts`, `packages/core/src/web_socket/web_socket.ts`.

**Observed unsafe patterns:** command kind dispatch casts, builder function casts, parsed input casts, response/event/session casts, listener-set casts.

**Risk:** medium-high. These are public generic APIs; incorrect narrowing changes consumer-visible return types.

**Target:** keep overload surfaces, introduce named dispatch helpers or discriminated command unions, and keep any unavoidable narrowing next to runtime validation.

### Group D — JSON.parse runtime boundaries

**Primary files:** `packages/core/src/handler/util.ts`, `packages/core/src/http/transport/utils.ts`, `packages/core/src/http/transport/fetch.ts`, `packages/core/src/sse/sse.ts`, `packages/core/src/web_socket/codec.ts`, plus tests/setup/config.

**Observed unsafe patterns:** raw `JSON.parse(...)` returning `any`, followed by direct use or broad assertion.

**Risk:** medium. Some paths immediately pass parsed data to struct decoders; others should return `unknown` or validate the shape.

**Target:** create `parseJsonUnknown(text: string): unknown` and, where needed, small guards such as `isSocketMessage`/`isServerEvent`.

### Group E — Test mocks and invalid runtime fixtures

**Primary files:** HTTP/SSE/WebSocket/client/interceptor specs and `packages/core/test/*.ts`.

**Observed unsafe patterns:** `as unknown as typeof fetch`, `MockWebSocket as unknown as typeof WebSocket`, `as never` to force invalid calls, broad event casts, and Vite plugin request/body casts.

**Risk:** low-medium. Test-only, but it weakens tests by letting mocks drift from runtime contracts.

**Target:** add typed mock factories in `packages/core/test/shared.ts`; use invalid-call helpers for runtime-negative tests; keep type-test negative assertions in `*.type.test.ts`.

### Group F — Definite assignment assertions in deferred helpers

**Primary files:** `packages/core/src/sse/transport/event_stream.ts`, `packages/core/src/web_socket/web_socket.ts`.

**Observed unsafe patterns:** `let resolve!`, `let reject!`.

**Risk:** low-medium. This is a common Promise deferred idiom, but TypeScript cannot prove initialization.

**Target:** replace with a small `createDeferred` helper that initializes through a captured object or throws unreachable if construction failed.

### Group G — Function type boundary in HttpContext token registry

**Primary file:** `packages/core/src/internal/context.ts`.

**Observed unsafe patterns:** `WeakSet<Function>`, `value as Function`.

**Risk:** low. Runtime behavior is constrained by `typeof value === 'function'`, but `Function` is too wide.

**Target:** use `type ContextTokenConstructor = (...args: never[]) => unknown` or a narrower object/function registry helper.

## Task 6: Remove definite assignment assertions from deferred helpers

**Files:**

- Modify: `packages/core/src/sse/transport/event_stream.ts`
- Modify: `packages/core/src/web_socket/web_socket.ts`

**Interfaces:**

- Produces: `createDeferred<T>(): Deferred<T>` without `let resolve!` / `let reject!`.

- [ ] **Step 1: Replace the deferred implementation with an object-initialization pattern.**

```ts
function createDeferred<T>(): Deferred<T> {
  const deferred = {} as Partial<Deferred<T>>
  deferred.promise = new Promise<T>((resolve, reject) => {
    deferred.resolve = resolve
    deferred.reject = reject
  })

  if (!deferred.promise || !deferred.resolve || !deferred.reject) {
```
