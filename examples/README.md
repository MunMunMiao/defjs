# Defjs examples

This directory contains exactly 76 Defjs project packages. Each package owns one integration need, one `src/index.ts` entry, and its business policy; no package imports another example's source. Protocol simulators, framework renderers, telemetry providers, and transport type adapters stay in project-local support files.

The patterns were re-expressed with public Defjs APIs after studying the linked upstream projects; source code was not copied. Every runner uses local Fetch, SSE, or WebSocket fixtures, credentials remain caller-owned, and reserved `.invalid` origins prevent examples from naming real resources.

## Run

Install the workspace dependencies, then start any project by package name:

```sh
pnpm --silent --filter @defjs/example-http-typed-status start
```

Each entry exports a named `main(): Promise<void>` and invokes it only behind [`import.meta.main`](https://nodejs.org/api/esm.html#importmetamain). Named exports hold the wire contract and reusable application invariant; `main()` runs a representative local scenario, prints one small semantic JSON result, and cleans up. Support modules have no executable guard. This follows the named-action and direct-run conventions in the [AWS JavaScript example standards](https://github.com/awsdocs/aws-doc-sdk-examples/wiki/JavaScript-code-example-standards), [Prisma](https://github.com/prisma/prisma-examples/blob/2d0ef305b4212e94e7ee7ef329ac2fee2dab4bae/orm/graphql-nexus/prisma/seed.ts#L55-L74), [Fastify](https://github.com/fastify/fastify/blob/b912c24f422adb59f6a165fee7bf78857762f079/docs/Guides/Getting-Started.md#L67-L96), [Nest](https://github.com/nestjs/typescript-starter/blob/c4d9330f5513eda0fb5df594f6b34a11fde1a934/src/main.ts#L1-L8), and [OpenTelemetry](https://github.com/open-telemetry/opentelemetry-js/blob/a0267be1394c12b2d401865d36adecf2529eeb0b/examples/grpc-js/client.js#L12-L45).

The repository uses the same standard checks as the published packages. One root TypeScript program validates every example together with the library sources and tests. Vitest runs all 76 example scenarios in isolated Node processes and compares each JSON result with the corresponding README `Expected result`.

```sh
pnpm typecheck
pnpm test
```

`pnpm build` always runs the full TypeScript check before producing package or documentation output. The per-example `start` script remains an interactive runner; it is not used as a test command.

## Example contract

Each project:

1. is a private workspace package with one `src/index.ts` entry;
2. exports a named async `main()` and invokes it only behind `import.meta.main`;
3. uses local Fetch, SSE, or WebSocket fixtures instead of external services;
4. prints one small JSON result that matches the Expected result in its README; and
5. owns and closes the resources it creates before returning.

Local TypeScript imports follow the workspace's bundler-resolution convention and remain inside their example package. Runners show one representative path; exhaustive status matrices and boundary coverage belong in package tests.

## Waves

| Wave | Meaning                                                          | Start here when                                                                           |
| ---: | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
|    1 | One transport or contract boundary with direct ownership         | Learning the core request, Struct, cancellation, SSE, or WebSocket shape                  |
|    2 | Application policy composed around that boundary                 | Adding correlation, bounds, cache, interceptors, framework scope, or lifecycle races      |
|    3 | Provider/runtime integration with stricter operational ownership | Integrating OIDC, SigV4, proxies, circuit breakers, OTel, or WebSocket framework sessions |

Wave is teaching order, not quality or production-readiness rank. Every wave still uses the same one-entry, offline, deterministic verification contract.

## Learning paths

- Wrong body accepted or status confused with data: start with [`http-typed-status`](./http-typed-status/), [`struct-zero-values`](./struct-zero-values/), then [`struct-response-validation-error`](./struct-response-validation-error/).
- Credential might reach the wrong service: use [`auth-basic-http`](./auth-basic-http/), [`auth-bearer-interceptor`](./auth-bearer-interceptor/), then [`auth-hmac-webhook`](./auth-hmac-webhook/) or [`auth-aws-sigv4`](./auth-aws-sigv4/).
- Old UI work wins or teardown hangs: use [`lifecycle-cancel-stale`](./lifecycle-cancel-stale/), [`lifecycle-deadline`](./lifecycle-deadline/), then the React or Vue lifecycle examples.
- Retry or replay could duplicate a mutation: compare [`resilience-retry-after-get`](./resilience-retry-after-get/) with [`resilience-idempotency-key`](./resilience-idempotency-key/) before adding a breaker or rate-limit scheduler.
- Streaming memory or queues grow: follow [`download-buffered-progress`](./download-buffered-progress/), [`sse-parser-buffer-limit`](./sse-parser-buffer-limit/), [`sse-bounded-queue`](./sse-bounded-queue/), then [`websocket-outgoing-queue`](./websocket-outgoing-queue/).
- Requests lack diagnosable but safe telemetry: start with [`context-correlation-id`](./context-correlation-id/), then metrics/logging, and finish with the OTel lifecycle examples.

## Neighboring choices

- [`http-repeated-query`](./http-repeated-query/) emits one key per array item; [`http-csv-query`](./http-csv-query/) emits one key whose individually encoded values are comma-delimited. Choose the server's declared wire format, not personal preference.
- [`cache-etag-revalidation`](./cache-etag-revalidation/) controls read reuse with `If-None-Match`; [`consistency-precondition-header`](./consistency-precondition-header/) protects a write with `If-Match`; [`consistency-resource-version`](./consistency-resource-version/) carries an application/provider version inside JSON.
- [`sse-parser-buffer-limit`](./sse-parser-buffer-limit/) bounds bytes before one event is parsed; [`sse-bounded-queue`](./sse-bounded-queue/) bounds parsed events waiting for a consumer. They protect different resources.
- [`websocket-reconnect-policy`](./websocket-reconnect-policy/) decides whether and how often to redial; [`websocket-outgoing-queue`](./websocket-outgoing-queue/) bounds sends while disconnected; [`websocket-owned-lifecycle`](./websocket-owned-lifecycle/) guarantees one owner closes and awaits the logical session.

## Current response-decoding boundary

Treat response status and body as separate runtime facts. Status does not automatically narrow a body union. Missing or `null` fields, an empty successful body, and body parse/read errors on a non-zero HTTP status can currently enter zero-value decoding; an incorrect non-empty value normally becomes `RESPONSE_VALIDATION_FAILED`. Applications that need strict malformed/empty `2xx` rejection must retain explicit business-invariant checks until the core behavior is remediated.
